# 要件

Java 版 [midi-chord-viewer](https://github.com/so-studnet/midi-chord-viewer) と同じことを Web アプリで行う。
Java 版で不満だった「アプリの音の遅延」と「音色」を改善し、後から機能を足しやすい構造にする。

## 決めたこと（2026-11-27 の壁打ち）

| 項目 | 決定 |
|---|---|
| 対象ブラウザ | PC の Chrome（Web MIDI が必要。Safari・iPad は対象外） |
| 音色 | 最初はピアノ 1 種類（Salamander Grand Piano） |
| アプリの音の役割 | Fantom-06 本体の音の補助のまま。オン/オフと音量を付ける |
| 鍵盤の表示範囲 | 61 鍵（C2〜C7、MIDI 36〜96）固定 |
| 公開 | URL で公開し、どの PC からでも開ける（Vercel） |
| 追加機能 | 後から決める（docs/roadmap.md の候補） |

## 機能（Java 版と同じ）

- MIDI 入力機器を選ぶ（前回の機器を自動で選ぶ。抜き差しに追従）
- 鍵盤の表示：押している鍵を濃い色、サステインで伸びているだけの音を薄い色で示し、音名を出す
- コード判定：0 音は「-」、1 音は音名、2 音は音程、3 音以上はコード名（オンコード・近似候補 `(?)` 付き）
  - 判定結果は Java 版と完全に同じ（2,821 通りで突き合わせ。`tools/java-golden/`）
- サステインペダル（CC64）を表示・判定・発音すべてに反映
- 全 MIDI チャンネルをまとめて 1 つの音集合として扱う
- アプリ内のピアノ音源で発音（オン/オフ、音量）

## 非機能

- 発音の遅延：MIDI 受信から React を通さず直接発音する。AudioContext は `latencyHint: "interactive"`
- 画面の更新：1 フレームに 1 回にまとめる
- 設定（機器名・音のオン/オフ・音量）はブラウザ内に保存

## 追加機能 1: 度数表記とキー（2026-11-27 決定）

- コード名の下に度数（ディグリー）を表示する。例: キー C で `Dm7` → `IIm7`、`G7/B` → `V7/VII`、`B♭` → `♭VII`
  - 書き方は `IIm7` 形式（日本で一般的）。音階外は `♭II ♭III ♯IV ♭VI ♭VII`。近似候補は `(?)`
  - 単音・2 音（音程）では度数を出さない
- キーは**平行長調基準**（Am の曲も C として扱い、`Am` は `VIm`）。表示は `C / Am`
- キーは自動判定（既定）。手動で 12 キーから選ぶ・「このキーで固定」もできる。指定はブラウザ内に保存
- コード名・音名の ♯/♭ はキーに合わせる（キー F なら `B♭`）。キー未判定のうちは Java 版と同じく ♯

## 追加機能 2: コード検索と記法（2026-11-27 決定）

- コードの種類を 30 → 42 に増やす（Web 版で追加: 5, 6/9, m6/9, 7sus2, 7(b13), 9(#11), 7(b9,13), 7(#9,b13), maj7(#5), maj7(#11), m7(11), m7-5(9)）
  - 追加した種類は後ろに置き、同点なら Java 版の種類が優先される。Java 版と結果が違うのは追加した種類に判定されたときだけ（テストで確認）
  - 5（パワーコード）は近似候補の探索には使わない
- 表示の記法を選べる：標準（Cmaj7 / Cm7-5）、日本式（CM7 / Cm7(♭5) / CmM7）、ジャズ記号（C△7 / C-7 / Cø7 / C°7）。度数表記も同じ記法に従う
- コード検索：いろいろな記法の入力（M7 / maj7 / △7、m7-5 / m7(♭5) / ø、7b9 / 7(♭9) / 7-9、C(9) = add9、全角も可）と度数での入力（IIm7、♭VII、ii7 は小文字 = マイナー）を読み取り、
  コード名（選んだ記法）・度数・構成音（音程に合った ♯/♭）・鍵盤上の位置（別の色）を表示し、▶ で鳴らせる。同じルートの全種類を一覧から選べる
- 試聴の音は音源だけに送り、画面の鍵盤やキー判定には影響しない
